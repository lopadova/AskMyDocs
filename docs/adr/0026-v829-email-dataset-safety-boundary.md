# ADR 0026 — Bounded generation and CLI-only safety boundary for case-study email datasets (v8.29)

- **Status:** Accepted
- **Date:** 2026-07-28
- **Cycle:** v8.29
- **Builds on:** ADR 0017 (multi-account connectors), ADR 0018 (sync
  observability), ADR 0021 (IMAP folder selection and email harness)

## Context

The case-study dataset can generate 30,000 deterministic messages and deliver
them through real IMAP APPEND calls. Two boundaries were incomplete:

1. the JSONL writer retained one file descriptor for every data/index shard
   until publish, so corpus size and shard fan-out could exceed a normal
   process limit;
2. destructive purge flags were guarded only by CLI intent. They had no
   environment fence, exact single-use confirmation or tenant-scoped forensic
   lifecycle.

This subsystem is an operator fixture harness, not a customer-facing product
write API. Adding HTTP or MCP mutations would broaden the attack surface
without creating a valid product use case.

## Decision

1. `JsonlDatasetWriter` uses one shared 64-handle LRU budget for data and
   fixture-index shards. A path is created once with `xb`, then reopened after
   eviction with `ab`. Eviction, finish and abort attempt flush and close for
   every affected handle and fail loudly with the complete error list. The
   limit is constructor-injectable for tests, not an operational bypass.
2. Generated bytes remain part of the contract. Tests compare complete hash
   trees produced with a two-handle budget and the normal budget.
3. Dry-run, validation, generation, estimation and destructive preview are
   offline operations in every environment. Any real APPEND or purge is
   rejected unless `APP_ENV` is `local` or `testing`; there is no override.
4. Every destructive form (`--purge-dataset`, `--purge-only`,
   `--purge-all-seeded`, and `--purge`) requires a DB-backed single-use token.
   Its persisted SHA-256 hash is bound to operation, actor, dataset identity,
   manifest/fixture checksum, normalized mailbox/tenant selection and canonical
   arguments. Consumption is protected by `lockForUpdate` and occurs after
   deterministic preflight but before the first remote mutation.
5. Each real mailbox operation opens a tenant-scoped `admin_command_audit` row
   before remote I/O and closes it as completed or failed. Rejections are also
   recorded. Audit arguments are an identifier-only allowlist and never contain
   credentials, message bodies or mailbox addresses.
6. The write surface remains deliberately CLI-only. No HTTP/MCP mutation is
   introduced for an environment-confined fixture harness. This is the
   documented R44 exception; generation, validation and preflight remain
   scriptable through Artisan services.

## Consequences

- generation has a constant file-descriptor ceiling independent of shard count;
- a copied, expired, consumed or argument-drifted token cannot authorize a
  different purge;
- multi-tenant selections create and consume one locked nonce row per tenant;
- audit failure prevents remote I/O, while a remote failure remains visible per
  mailbox;
- automation must perform an explicit preview and pass the returned token and
  same actor to the mutating invocation;
- live IMAP/PostgreSQL/Gmail certification remains an external gate and must not
  be inferred from the offline suite.
