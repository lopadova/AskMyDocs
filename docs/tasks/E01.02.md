# E01.02 — Two-factor authentication

Status: `VERIFIED_LOCAL`

## Implemented

- Feature flag `AUTH_2FA_ENABLED` remains off by default; disabled endpoints retain the stable 501 contract.
- Enrollment creates a 160-bit-derived Base32 secret and returns an `otpauth://` provisioning URI once.
- The secret is encrypted at rest; it is hidden from the `User` serialization and `/api/auth/me`.
- Confirmation implements RFC 6238-compatible six-digit TOTP with a ±1 time-step tolerance and replay protection.
- Confirmation returns ten recovery codes once; only password hashes are persisted and successful recovery codes are consumed.
- Disable requires a valid TOTP or unused recovery code and clears all factor material.
- Invalid verification never enables the account.
