# AskMyDocs / Sorgente PactAuth

## Delivery status

The **OAuth authorization layer is implemented** for the Sorgente client at
commit `729cb4aba98efb9b7a5056f64aa79ebe0f7e9e62`. PactAuth is the application
profile agreed with that client: Authorization Code + PKCE S256 and the
`pact:delegate` scope. It is not an authentication standard defined by PACT Core.

**Delegation is unavailable.** Neither this checkout nor the main AskMyDocs
checkout has a PACT server, PACT library, registered contract or Sorgente object
adapter. Authentication does not establish A2A/PACT compatibility. Both protected
PACT URLs return HTTP 501 `pact_transport_unavailable`; no Agent Card, A2A
interface, accepted task or supported contract is invented. Discovery exposes
`pact.transport_available: false`, and consent shows the same limitation.
Sorgente can finish OAuth and show an authorized connection, but its subsequent
negotiation must fail until a real transport and adapter exist.

Verified runtime: PHP 8.4.25, Laravel 13.34.0, Sanctum 4.3.3, Laravel MCP 0.9.6.
No new dependencies were added. The independent Sorgente `Pact\Pact` autoload
problem was not modified.

## Origins and metadata

Official production origin: `https://askmydocs.padosoft.com`.
Development checkout: `/Users/marco/www/AskMyDocsDev`, served by Herd at
`https://askmydocsdev.test`. `APP_URL` is already aligned with Herd.

With PactAuth enabled, public GET `/.well-known/oauth-authorization-server`
returns JSON without a redirect. The PactAuth portion on development is:

```json
{
  "issuer": "https://askmydocsdev.test",
  "authorization_endpoint": "https://askmydocsdev.test/oauth/authorize",
  "token_endpoint": "https://askmydocsdev.test/oauth/token",
  "registration_endpoint": "https://askmydocsdev.test/oauth/register",
  "response_types_supported": ["code"],
  "code_challenge_methods_supported": ["S256"],
  "scopes_supported": ["kb:read", "kb:chat", "pact:delegate"],
  "pact": {
    "endpoint": "https://askmydocsdev.test/api/pact/a2a",
    "card_url": "https://askmydocsdev.test/.well-known/agent-card.json",
    "producer_id": "urn:askmydocs:pact",
    "transport_available": false
  }
}
```

Discovery also preserves the existing OAuth revocation and public-client
metadata. MCP discovery at `/.well-known/oauth-authorization-server/oauth/mcp`
retains its own issuer, registration and scopes. No tenant, project, user or
credential is published in discovery. The issuer comes from `APP_URL`, never
the incoming Host header, and PactAuth rejects non-origin `APP_URL` values.

POST `/oauth/register` routes Sorgente registrations (or explicit
`pact:delegate` registrations) through strict PactAuth validation. Existing MCP
registrations retain their behavior. The exact Sorgente request without a scope
field is supported. No client secret or refresh token is issued for PactAuth.

GET `/oauth/authorize`, GET `/oauth/consent` and the session-only
`/api/oauth/authorization/{handle}` endpoints reuse the existing login and
consent UI. Consent requires an active account with verified email, explicit
company and project selection, and a CSRF-protected approval or denial. No
membership or tenant is created by authorization. Approval preserves `state`
and returns the authorization code and the origin issuer to the exact callback.

POST `/oauth/token` accepts form encoding, validates S256/client/callback,
expiry and a hash of the single-use code, and consumes it with a conditional
update inside the transaction. The returned Bearer is the opaque Sanctum secret
without the optional `id|` prefix, which Sorgente's RFC 6750 check rejects.
Sanctum supports lookup by its SHA-256 hash without that prefix. REST/MCP token
formats remain unchanged. Default PactAuth expiry is one day; TTL is bounded
to 60..31536000 seconds, also respecting the Sanctum maximum lifetime.

## Local configuration and preregistration

The committed defaults leave PactAuth disabled and the client-origin allowlist
empty. This checkout's ignored `.env` has been enabled for local work only:

```dotenv
PACT_AUTH_ENABLED=true
PACT_AUTH_ALLOWED_CLIENT_ORIGINS=https://sorgente.test
```

The additive migration `2026_10_21_000002_add_pact_oauth_project_bindings.php` is
applied locally. Apply it through the ordinary migration process elsewhere.
Its rollback revokes only PactAuth grants and preserves legacy REST/MCP keys.

Set this **on Sorgente** to test against the development checkout:

```dotenv
PACT_AUTH_ASKMYDOCS_URL=https://askmydocsdev.test
```

No public client ID was created in the live development database: leave
`PACT_AUTH_ASKMYDOCS_CLIENT_ID` unset to use DCR. Its callback is generated by
Sorgente as `https://sorgente.test/{company-slug}/integrations/pact-auth/askmydocs/callback`.
Each complete URI is stored and compared exactly. No wildcard, userinfo, query,
fragment, encoded path separator or arbitrary callback path is accepted.
Origin includes schema, host and port. Other Sorgente origins require explicit
operator configuration. HTTP additionally requires `PACT_AUTH_ALLOW_LOCAL_HTTP=true`
and local/testing; production always requires HTTPS.

To use a preregistered public client, an operator can run:

```sh
php artisan pact-auth:client --redirect-uri='https://sorgente.test/COMPANY-SLUG/integrations/pact-auth/askmydocs/callback'
```

Substitute the actual lowercase company slug. Configure the resulting public
UUID in `PACT_AUTH_ASKMYDOCS_CLIENT_ID`. This also works when
`PACT_AUTH_DYNAMIC_REGISTRATION=false`. Never put tokens or credentials in chat.

## Authorization and revocation boundary

New grants record client, authorizing user, tenant, project and a hash of the
project membership role, folder/tag scope and current RBAC permissions. They
grant only `pact:delegate`; they do not grant KB REST, MCP, ingestion or email
abilities. Even a super-admin must have membership in the selected project.
The Bearer gate rechecks active/verified user, active tenant, client scopes and
origin allowlist, feature flag, expiry, token record and current membership
snapshot on every PACT request. Authority changes require a new authorization.
Payload tenant/project fields cannot widen the stored grant.

The existing `/oauth/connections` page displays the selected project and
supports owner-only revocation through CSRF-protected session endpoints.
POST `/oauth/revoke` also accepts the opaque Bearer and matching public client
ID. There is no refresh flow for this profile. Legacy token grants are neither
migrated nor revoked on upgrade. PactAuth Bearers cannot manage other grants
or authenticate against the existing REST/MCP routes. Session cookies and
ordinary API keys cannot authenticate the PACT endpoints.

## PACT contract gap

Sorgente requires A2A **1.0** JSONRPC, PACT Core **0.2**, extension activation
headers, and the following exact contract from its resources:

| Component | Sorgente requirement |
| --- | --- |
| Contract | `urn:sorgente:pact:delegation` version `1.0.0` |
| Input | `urn:sorgente:pact:delegation:1:input`, SHA-256 `93ca266e6314945857d9c655bdaf800a041003c8f3b790fb0c3aef997889c60d` |
| Output | `urn:sorgente:pact:delegation:1:output`, SHA-256 `92291e609d834454229e19fd25db86cf715bcc84f544f806c3aa327d29b37a4f` |
| Question answer | `urn:sorgente:pact:delegation:1:answer`, SHA-256 `7222b0c89e429c8882e67b028cd51871797f9ea0cfb8d7c594c0a5a2d6e3b875` |

The schemas were read, not just their identifiers: input has typed `sorgente.*`
objects, output signatures and criteria; output has typed objects with data and
provenance; an answer has nonempty text. AskMyDocs has no corresponding schema
registry or mapping from these objects to its KB search/read operations and
back to validated outputs. No compatibility claim can be made from MCP's
JSON-RPC support alone. A future adapter must validate the real inputs/outputs,
apply document ACLs and the pinned project, implement task lifecycle,
idempotency and extension negotiation, and publish only implemented contracts.
The present 501 responses deliberately stop negotiation and execution.

## Cloudflare

On 21 October 2026 a credential-free GET of production discovery returned
**200 text/html**, not OAuth JSON. It passed through Cloudflare but contained
no recognized challenge markers. This proves the advertised OAuth endpoint is
not available there yet; it does not prove an Access policy is blocking it.
No production policy, DNS, deployment or account setting was changed.

Sorgente's current PactAuth HTTP client sends no
`CF-Access-Client-Id`/`CF-Access-Client-Secret` headers. If Access protects the
backchannel, a coordinated Sorgente extension is required: operator-configured,
server-only service credentials per provider, added to discovery, DCR and token
requests on the already validated exact issuer origin, with redirects still
disabled. Apply the same credentials to the authenticated Agent Card and PACT
RPC client. Retain `Authorization: Bearer ...` for application authorization;
do not replace it with the Access credential or send secrets through browser
parameters, serialized props or logs.

An operator must make the nonsensitive discovery GET publicly reachable and
scope any service-auth policy to the exact required paths. Preregistration can
avoid DCR, but cannot remove the token/card/RPC backchannel requirement. Do not
disable Access globally. The outbound API connector's
`X-AskMyDocs-Cloudflare-Token` is an unrelated custom WAF-rule header and does
not supply Cloudflare Access authentication for Sorgente.
See [Cloudflare service tokens](https://developers.cloudflare.com/cloudflare-one/access-controls/service-credentials/service-tokens/)
and [A2A 1.0 specification](https://a2a-protocol.org/v1.0.1/specification/).
