# Retrieval benchmark v2

Synthetic corpus + labelled queries for `kb:benchmark` that can actually FAIL.
v1 (`resources/benchmark/`, 5 docs, 14 queries) is saturated (nDCG@5 ~0.997).
v2 uses a fictional company, **Northwind Logistics**, across ten domains
(billing, fulfilment, warehouse, support, HR, security, API, retention,
incident response, release engineering).

| class | queries | what it stresses |
|---|---|---|
| paraphrase | 17 | query shares almost no content words with the target |
| hard_negative | 16 | accepted doc must beat a superseded/deprecated/look-alike sibling |
| identifier | 13 | ticket ids, error codes, endpoints, paths, commands, `-sandbox` |
| context_dependent | 10 | same sentence in several docs; only the heading disambiguates |
| short_ambiguous | 10 | 1-3 word queries, graded multi-doc relevance |
| code | 10 | symbols/behaviour/location answered by source files |
| refusal | 10 | not in the corpus: `relevance: {}`, `expect_refusal: true` |

86 queries (47 en / 39 it, some cross-lingual). 40 corpus files: 34 markdown
(15 canonical, 2 `rejected-approach`, 17 plain) + 6 code (3 PHP, 2 TS, 1 Python).

## Conventions
- **Flat corpus, unique keys.** No subfolders; key = basename without extension,
  unique across all extensions.
- **No secrets.** Code reads config via env var *names* only.
- **Hard negatives.** `refund-policy-2023` and `api-rate-limits-2022`
  (`superseded`) and `access-password-legacy` (`deprecated`) reuse the accepted
  sibling's wording with different numbers. In `hard_negative` queries the old doc
  is omitted from `relevance` (= 0) and never `expect_citation`. Look-alikes
  (sandbox vs production keys, Milano vs Bologna) are encoded the same way.
- **History queries.** `identifier` queries naming an old doc explicitly rate it 3.
- **Identifiers** occur in exactly one doc; `expect_related` follows `related:` wikilinks.
- Binary fixtures (PDF/DOCX) are generated by a separate step and not used here.

## How to extend
1. Add the doc to `corpus/` (12-40 lines md, 40-120 code); canonical docs need the
   v1 frontmatter and `slug` = basename.
2. List the key in the `queries.yaml` header under its domain.
3. Add queries with `class`, `lang`, graded `relevance`, `expect_*`; keep class minimums.
4. A new superseded sibling needs a `hard_negative` and a history `identifier` query.
